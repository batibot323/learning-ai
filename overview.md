# AI Agents Learning — Overview

## Why

I use AI tools daily. I want to understand how they actually work — not to become an ML researcher, but to use them better and make smarter decisions about where they fit in engineering work.

The gap I'm filling: I can prompt, but I don't deeply understand the mechanics of agents, context management, tool use, and evaluation. That limits how well I can leverage these tools and guide my team on when/how to use them.

## Who I Am

Engineering manager with technical depth. I learn fast when I have good material. I prefer reading dense, well-written content and watching talks from practitioners who've built real systems.

I'm not starting from zero — I use coding agents regularly and have intuitions about what works. Now I want the mental models to back up (or correct) those intuitions.

## What I'm Learning

**Scope:** AI agents for software engineering — how they work, how to build them, how to evaluate them, how to think about them strategically.

**Not in scope:** ML fundamentals, training models, fine-tuning, research-level AI safety. I'm focused on the applied/engineering side.

## Constraints

- **Can read Anthropic blogs** — their engineering content is excellent and directly applicable
- **Can only run Kiro IDE** — no access to Claude Code, so hands-on exercises need to work within Kiro's tooling (MCP servers, hooks, steering files, etc.)

This means some exercises designed for Claude Code need adaptation — but Kiro supports MCP natively, so tool design and context engineering exercises translate well.

## How I Learn

- **Read first.** Primary sources (Anthropic engineering blog, official docs) over summaries and hot takes.
- **Watch selectively.** Conference talks and practitioner deep-dives, not hype content.
- **Build to understand.** Small experiments to test my mental models — adapted to work in Kiro.
- **Measure, don't vibe.** When comparing approaches, use evals not gut feel.

**Cadence:** 1–2 weeks intensive. Weekday evenings for reading/watching, weekends for whole-day hands-on exercises.

## Success Criteria

I'll know I've succeeded when I can:

1. **Explain** the difference between workflows and agents, and when to use each
2. **Build** a simple agent from scratch (no framework) that actually works
3. **Evaluate** an agent's performance systematically, not just by feel
4. **Advise** my team on where agents add value in our SDLC and where they don't
5. **Debug** agent failures by understanding what's happening in the loop, not just retrying with different prompts
